# CUSUM / BOCPD / Markov Switching / Bipower Jump 机制与三态框架评估

日期：2026-08-28  
状态：文献机制评估，不是中证1000实证，不授予路由、策略或生产权。

## 1. CUSUM：累积偏离告警器

### 主要逻辑

对每一个新观测，累积“当前数据相对参考分布偏离了多少”。只有持续的同方向偏离
才会把累计和推过告警线；随机单点噪声通常不足以触发。

### 与本框架的关系

- 最合适的职责：检查波动率水平、log-vol 均值或连续波动占比是否正在发生持续改变；
- 可以成为 `transition_hazard` 的一个候选实现；
- 对“高位突然断头”的第一根无法预知，只能在偏离开始累积后报警；
- 它不告诉我们高波动率时哪个通道策略应该赢。

### 主要风险

参考分布、目标偏离尺度和告警阈值本身都是参数。金融高频数据的异方差、厚尾和微观结构
噪声会改变虚警率。因此 CUSUM 必须使用严格滞后的参考分布，并与最小状态寿命或滞回共存。

## 2. BOCPD：在线估计“本制度已运行多久”

### 主要逻辑

Adams 和 MacKay 不只输出“变/没变”，而是维护当前 run length 的概率分布：
当前生成机制已经持续了多少个观测，以及此刻发生 changepoint 的后验概率。

### 与本框架的关系

- 直接对应本框架的 `state_age` 和 `transition_hazard`；
- 可以对“波动率记忆”给出比固定最小寿命更完整的概率表示；
- 在用户框架中，它应该挑战“简单实现波动率+滞回”仪器，而不是直接取代交易策略；
- 它与 P34 高频分散线没有直接选 P 关系，只能为完整账户提供状态转移证据。

### 主要风险

hazard prior 、段内概率模型和预测分布决定敏感度。若用高斯段内模型处理厚尾收益，
极端棒可能被误当成新制度。实现时必须保存每一根的在线过滤后验，禁止用事后全样本分段。

## 3. Hamilton Markov Switching / HMM / IMM：多模型概率状态

### 主要逻辑

Hamilton 将时间序列参数看成不可观测的离散 Markov 状态的结果。状态通过转移矩阵具有持续性，
当时数据通过似然更新当前状态的过滤概率。HMM 是这一思路的通用表达；IMM 则进一步让多个
动态模型同时运行并按概率混合。

### 与本框架的关系

- 它是“低/中/高波动率概率”最直接的软状态挑战者；
- 可以避免刚越过一条阈值就把整个账户翻转，但仍需要状态概率到仓位的独立滞回/限速器；
- 可以作为日后 IMM 的最小基线：低波动模型、正常滤波模型、高波动通道模型并存；
- 它不能把三个状态概率直接当成三个策略已有收益证据。

### 主要风险

- 状态标签会互换，必须用严格经济排序重标；
- 全样本 smoothed probability 使用未来数据，交易只能使用 filtered probability；
- 转移矩阵的固定持续性可能无法表达突发跳变，所以它与 BOCPD/CUSUM 是互补而不是互相替代；
- 高容量 IMM 只有在简单 HMM 相对硬状态基线有明确增量后才有研究理由。

## 4. Bipower Variation：分清“波动率变大”与“跳了一下”

### 主要逻辑

实现方差 RV 同时包含连续扩散波动与跳跃。Bipower variation 在给定条件下对稀有跳跃较稳健；
RV 与经标准化的 BV 之差可以估计跳跃二次变差成分。

### 与本框架的关系

- 解决用户提出的核心混淆：同样是高波动，可以是可持续的高速通道，也可以是一次性断头/尖底跳变；
- `continuous_volatility_share` 可以帮助判断高态是否有连续通道土壤；
- `jump_share` 只能作为风险负担或状态解释，不会告诉下一根向上还是向下；
- 项目既有 `jump_variation_share` 属性可作最小实现起点，但已撤权的 `causal_jump_gap_shock`
  独立交易责任不得因文献归档而复活。

### 主要风险

微观结构噪声、非同步样本和盘中观测数不足会扭曲 RV/BV。完整当日 BV 在盘中尚不可见；
任何运行时使用都必须是上一完成窗或严格盘中前缀，不得用收盘后全日结果回填。

## 5. 四方法怎样组合，什么不组合

```text
滞后实现波动率 + 滞后 jump/continuous 分解
                         |
             简单硬三态参考仪器
                         |
       +-----------------+-----------------+
       |                                   |
CUSUM / BOCPD                        Hamilton/HMM
转移告警挑战                       软状态概率挑战
       +-----------------+-----------------+
                         |
          同一组完整三态策略终审
```

第一阶段不应该同时把四个方法塞进一个高自由度控制器。正确顺序是：

1. 先冻结简单、可重放的滞后波动率硬三态基线；
2. CUSUM 和 BOCPD 只挑战转移识别；
3. Hamilton/HMM 只挑战硬状态表示；
4. bipower jump 只挑战“高波动类型”的解释与风险缩放；
5. 每个挑战者都必须放回同一完整账户、同一成本和同一自然年顺序合同。

## 6. 对用户三态框架的当前裁决

- 框架方向成立：波动率有记忆，适合成为状态轴；
- 但“高波动=通道必胜、低波动=必须空仓”仍是待验假设，不是已知规则；
- 外部方法不应该在第一阶段代替简单基线，否则无法知道增量来自哪里；
- P34 往高频的回撤错位研究是独立线，不应该被 HMM 或 changepoint 候选提前绑定；
- 当前最诚实状态是：文献机制已吸收，研究框架已冻结，本地策略证据仍为零。
