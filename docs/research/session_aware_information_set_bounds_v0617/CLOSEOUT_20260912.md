## Why a newly computed hash cannot reopen v0.6.17

The frozen protocol explicitly required an identity that demonstrably predated the replay request. Computing a SHA-256 today for a newly selected 349,923-row candidate or for a reconstructed leg table would make the same observation act as both selection and verification. That would erase the preregistered identity guarantee rather than satisfy it.

Therefore none of these actions are permitted under v0.6.17:

- select a present-day 349,923-row file and call its newly computed SHA the old expected SHA;
- reconstruct v0.6.15 legs from current code and call them the frozen universe;
- substitute the known 350,561-row FactorLab 1m surface;
- delete session-edge / gap legs to improve coverage;
- infer support topology from neighboring closes or wall-clock buckets;
- weaken the identity gate because implementation tests passed.

A future study could ask a similar information-set question only under a **new explicitly versioned prospective identity protocol**. It could not be represented as completion of v0.6.17.
