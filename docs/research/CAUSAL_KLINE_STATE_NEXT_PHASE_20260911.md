# 下一阶段权威叙事：面向下游分桶的因果 K 线风险属性

日期：2026-09-11。来源：用户在 V19 阶段性收口后明确要求，研究必须贴近行情演变与下游状态/策略分桶的实际用途，但本仓不开发具体策略。数学与统计决策继续由研究执行者负责。

## 1. 本仓为什么识别状态

**把行情演变中已经发生、在决策当时可以知道的 K 线风险属性及其变化，表达为下游能够按时点消费的状态、转移和适用性信息。**

目标是帮助下游跟踪市场环境、区分策略适用条件，而不是追求后验图形解释或分类准确率的小数点。实用导向不等于在本仓选择买卖、方向、仓位或路由。

本仓拥有波动水平/扩张收缩、冲击/再冲击、UNSAFE/RECOVERING/NORMAL 风险状态和恢复信息。Range/UpTrend/DownTrend 父结构仍属 two-wave 仓；具体策略及其经济验收仍属相应策略仓。本次不修改其他仓、FactorLab/DataHub 的生产注册或在线权限。

## 2. 从什么起点出发

V16/V17/V18/V19 及 residual audit 的原始代码、冻结对象、报告、receipt 保持不变。V19 是当前冻结的风险状态基线，不启动“修小数点”的 V20。

但阶段性完成不等于实用价值或生产就绪已经证明。现在分开记录三种状态：

- 科学基线：V19 在既定参考定义下具有 reusable Validation 支持。
- 工程交付：当前开始接口、因果回放、消费者接入验收；不是已经上线。
- 下游效用：风险环境区分与策略适用性帮助需要单独证据；盈利、回撤改善尚未证明。

V19 的二元风险持续识别 recall 不等于新风险提前捕获率；episode 在任一点重叠即算捕获，不等于整段无遗漏。既有 episode 指标来自固定 E-15 checkpoints，不是全秒级轨迹验收。

close-confirmed 规则在定义上阻止提前退出，因此“零提前 NORMAL”是约束满足与定义一致性证据，不是所有提前退出都无效的证明。阈值附近的残差解释也不是不可改进性定理。历史封存材料保留，当前措辞以此限定为准。

## 3. 因果是硬约束，不是宣传语

这里的 causal 指单边可计算、无未来信息，不代表干预因果识别，也不承诺在首跳证据出现前预测首跳。

设决策时点为 t，交付状态只能由 t 时已经可得的信息构造。当前未收盘的 final_state、事后 episode 终点/持续长度、未来收益/波动、最终路径类别只能出现在独立评价侧，不能进入在线属性或分桶键。

E-15 临时快照、5m 收盘确认事件必须分别记账；不得用后来确认的状态覆盖早先快照。新 shock 的恢复时钟仍按冻结规则处理，不把首跳年龄替代最近 shock 年龄。

已有 available_at 继续表示历史数据检索可得时间。另行使用 observation_time、observation_known_at、decision_time、published_at，并标注 owner_realtime_assumption 或实测 reception log。不得伪造已测延迟；没有接收日志不自动否定用户已澄清的历史因果研究口径。

## 4. 要交付什么，而不交付什么

交付两个相互隔离的数据面：

**因果属性面**：标的、时钟、上一已确认状态、当前临时/已确认状态、状态转移、退出待确认标记、数据可用性及原因、最近冲击年龄和可用时的冻结恢复概率、版本身份。各字段须注明是已验收属性、工程元数据还是未验证候选。

**后验评价面**：最终参考状态、完整 episode、后续风险结果，只用于衡量上述属性，不与消费者输入混装。

下游可以获得例如 UNSAFE|E15_PROVISIONAL 或 RECOVERING|PRIOR_CONFIRMED_EXIT_PENDING 的属性键。该键不是交易策略桶的最终动作映射。NORMAL 不表示安全保证；UNSAFE 不等于看空或一律不交易；RECOVERING 不等于看涨或开仓许可。数据不可用必须是 UNAVAILABLE，不得补 NORMAL；恢复概率不可用不得补 0 或 1。

HighVol 等其他属性不能在交付时偷偷变成 V19 的第四状态；增量属性另列来源、定义和验证状态。

## 5. 下一阶段顺序与验收

### D1 — 契约与首个适配切片（本次落实）

建立 CONTRACT.md、机器可读 PROGRAM_STATE.json、E-15 状态适配原型与合成测试。原型只包装冻结 V9 输入状态并复现 V19 保持规则；不加载行情、不拟合、不接交易系统。

必须拒绝当前 final_state/未来路径输入；缺字段明确不可用；禁止提前发布、延迟回填和 E-15 快照跨收盘无限沿用；输出记录不可变。合成测试通过只表示这个切片符合契约。

### D2 — 冻结组件的因果事件回放与消费者验收（下一项实际任务）

以现有封存代码和有界数据/产物实现逐事件的 E-15 与 close 双时钟回放，接入冻结 V16/V17 概率及其 unavailable gating。不得改变基线参数、参考定义或准入 cohort 来换取一致性。

先固定输入 manifest、代码/配置身份与验收规则，再执行。对可用行要求状态与冻结实现逐行相同，概率与冻结表一致（沿用已有浮点容差）；报告所有差异，而非只看 pooled 准确率。

验收包括：未来数据扰动不改变已发布前缀；发布记录不回填；首次进入/重新升级/恢复/确认退出可区分；开市、午休、日终、缺口、迟到与重复观察的确定性语义；按 as-of 接入的覆盖率、不可用比例、有效提前量和切换频率。实际接收日志未具备时，延迟项明确为假设或未测，不制造日志。

先在会话可执行环境完成小规模/单元检查；需要全量数据而不可在会话执行时按既有云端—本地协议列最小需求。Actions 不是默认计算地点。本次没有派发回放或生产任务。

### D3 — 有实际对象的风险分桶效用评价（协议先行，尚未执行）

问题不是“是否像自己的标签”，而是“在相同决策时点与可用信息条件下，状态/转移是否区分了下游关心的后续风险环境”。候选评价对象限定为后续实现波动、冲击再发生、风险持续与恢复；不使用收益方向、PnL 或仓位优化作为本仓目标。

在看新结果前冻结风险 endpoint、未来窗口边界（与输入不重叠）、基准、覆盖要求与最小实际效应。优先沿用 15/30/60m 物理尺度，不能凭历史表现挑时点/窗口；未来标签只存评价面。至少与上一已确认状态/简单历史波动基准在匹配时段和覆盖条件下比较，报告风险桶占用、NORMAL 桶风险泄漏、事件去重后的捕获/误报、转换延迟与稳定性；按交易日或依赖块给不确定性，不能把重叠行当独立事件。

若只获得自定义标签一致性而没有上述增量效用，不宣布分桶有效。若具有因果可得性和实际风险区分价值，可形成消费者交付证据；策略仓仍须独立验证动作映射、交易成本和经济收益，本仓不得借此恢复 payoff router。

## 6. 什么微调值得做

优先：修复可得性错误、时间口径、缺失原因、版本错配、接入一致性，以及由明确消费者需求提出的可证伪风险属性问题。

不做：为了更高 accuracy 调基线阈值、事后选更晚 checkpoint、靠未来状态分桶、把阈值触发本身当作经济效用证明。

确有新因果属性需求时，可以建立独立候选并回到 Development 研究；保留 V19 作为基准，不能改写已封存 V19。新版本须有具体用途、失败条件和结果前冻结协议，不必为了版本号立项。
