## 1. 用户意图与存储职责

本地FactorLab与DataHub是存储核心，云端私有仓库是高能力研究AI的临时研究工作区，不是另一份独立生产真源。用户要求把本地新增数据、基础设施、持久化研究成果、完整综述与引用文献增量上传，再由云端继续研究。

当前问题不是“把IIR参数调好”，而是：在共同波动环境变化之外，能否识别某些尺度突然异常活跃、少数K线集中完成大位移、或孤立跳变的条件结构？这种结构在科创50与中证1000为何不同？哪些只是事后能描述，哪些能在事件之前辨认？

**本轮只研究市场指数K线与风险状态，不开发交易/期权/期货策略，不运行账户或下单。** ETF只是用户允许的替代数据载体，不等于ETF和指数的微结构在统计上相同。已取得最长有界指数3秒数据后，本次新增原始数据选两指数，不再重复上传ETF秒数据。旧ETF结果保留为历史证据，不冒称指数实证。

## 3. 已经知道什么，以及不能如何解释

### 原始尾部与标准化尾部

2021—2023冻结阈值，2024—2025重复历史评价。相同1分钟绝对log收益阈值约29.036bp，标准化阈值约3.907；标准化使用事件之前的滚动波动。

“既大且异常”的事件落入事前高波动桶：中证1000约93.31%，科创50约59.02%。但高桶分别覆盖约65%与45%的时间，不能把此数称为聚集率或预测准确率。单看标准化异常，捕获率约61.53%与40.72%，不是标准化后都达到90%。两者1分钟标准化事件均有时间聚集证据，但大量为簇内第一次事件；聚集性不能保证首跳提前可知。

### 因果波动工具V1：环境可预测，普通时段突变仍漏报

多尺度log方差ridge，过去5/30/480分钟波动及已知实体/边界gap、日内时钟。2021—2022拟合、2023校准，模型固定后依次检验2024、2025。未来15分钟sigma定义为t+1..t+15均方收益的平方根，与过去对比窗口不重叠，不跨午休/隔夜；不是累计涨跌幅或交易方向。

| 主尺度15分钟 | 中证1000 | 科创50 |
|---|---:|---:|
| 多尺度log sigma RMSE | 0.3265 | 0.3229 |
| 沿用过去波动RMSE | 0.4073 | 0.3833 |
| 高波动状态召回率 | 91.87% | 86.59% |
| 标记高状态的时间比例 | 75.08% | 56.88% |
| 翻倍告警精确率 | 94.69% | 91.35% |
| 翻倍告警召回率 | 21.54% | 28.43% |
| 每半日开市30分钟后翻倍召回率 | 1.47% | 0.46% |

翻倍还要求达到真实高波动桶；固定概率≥0.5告警。这些是逐分钟重叠预测窗口，不是独立冲击数。漂亮的精确率主要来自开市季节性；首相位非重叠取样会偏向开市，必须保留全部相位与密集时点，不能挑最好相位。原型没有证明能预测大部分普通时段突发，未通过交易路由或最大回撤改善。固定阈值失败也不是所有可能方法都不行的证明。

### 分辨率与波形

此前科创50ETF真实3秒状态的15/30秒网格能看到分钟遗漏的往返。ER原始方差随更细采样下降，但归一化方差/CV²与重复报价比例并不支持“最高频已消失”或“15秒最优”。固定物理回看期与固定根数回看期必须分开；方差小也可能是稳定低效率或报价离散化。

较早固定滤波算法研究支持位移集中度/相位与捕获下降的部分关联，但没有把少数后验窗口变成可实时部署的门控。旧第四轮两份源码hash缺口仍是历史事件；新研究通过不能消除旧事件。不要引用原零成本指数账户收益作为市场风险门控有效性的证据。

## 5. 建议云端下一步怎样推进

先读原文和源论文，核查其方法是否真的能应用到当前数据粒度。优先研究价格层可实施的跨尺度条件异常、尾部/跳变/局部burst区分以及事件簇首跳与后续风险。订单簿脆弱性、撤单、期权隐含事件风险先标记输入不足，不用替代变量冒充已识别机制。

第一步先写结果前研究协议和可检验假说：固定比较窗口、相同物理H、日内季节性、事件阈值、尺度能量的单边估计、训练/校准/验证角色、标签重叠purge和评价统计单位。用共同交易日/会话以及事件级去重检验，保留不同分钟源repair/缺失的影响。

评价不是普通准确率一项：同时报告风险桶时间覆盖、Clean桶事件泄漏、事件召回/精确率、幅度加权泄漏、提前量、首跳与后续事件拆分、开市与普通时段拆分、同物理回看与随机/季节参照。仅观察到当前异常应叫检测，不叫预警；完成窗口才知道的标签只可验证，不能当输入。

不要以当前已知极端案例反复调参后再把同一案例称为独立确认；不要把文献中的相关、自激励或条件强度误写为干预因果关系。条件风险能降低到什么程度，需要实际数据证据，不承诺Clean桶零风险。

本次交接不替云端预定模型赢家、阈值或最优频率。云端可以先完成机制/数据可行性与协议，再按用户指示推进；不要自动恢复旧策略账户或运行旧模板的年度训练循环。
